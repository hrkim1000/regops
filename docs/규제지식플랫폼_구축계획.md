1개 규제영역(EU MDR + MFDS 의료기기)·1개 사업부로 범위를 좁혀 탐지 커버리지와 인용 정확도를 계량 검증한 뒤 확장.

## 3. Problem — 현재 규제 대응 방식의 5가지 구조적 한계

**01. 규제 변화 인지가 사람에 의존**
미국 연방관보만 2025년 23,690건 발행. 국가별 담당자 수동 모니터링은 누락·지연이 구조적으로 발생.

**02. 지식이 문서와 개인에 흩어져 있음**
PDF·이메일·개인 엑셀에 분산. 담당자 이탈 시 해석 근거가 함께 사라짐(RA 인력의 40~52%가 현직 2년 미만).

**03. 동일 질문에 매번 재조사**
'이 변경이 재허가 대상인가'류 질의가 반복되지만 축적되지 않음. 조사 시간이 제품 출시 리드타임에 직결.

**04. 규제-내부통제 매핑 부재**
규제 요건과 사내 SOP·통제 항목이 연결되어 있지 않아, 개정 시 영향 범위를 사후에 수작업으로 산정.

**05. 비준수 비용이 크고 후행적**
FDA 483·경고장 관련 비용은 미국 의료기기 산업 연 $2.5~5B 추정. 2025년 CDRH 경고장 54건(전년 43건).

> **결과** — 규제 대응이 '리스크 관리'가 아니라 '사고 수습'으로 운영된다.
> 2025년 의료기기 리콜 1,143건 · 5.837억 유닛 영향 · Class I 145건

*출처: Federal Register 문서 통계, Elemed Global Regulatory Affairs Workforce Report 2024, Emergo(CDRH 2025 경고장 리뷰), FDA CDRH 리콜 데이터 분석, 산업 비용 추정 연구*

## 4. Market — 소프트웨어 $2.5B, 대체 가능한 서비스 예산 $4.3B

**RIM 시장은 신뢰도가 높다** — 독립 리서치 2곳이 2025년 기준 $2.5B / $2.56B, CAGR 9.1% / 10.3%로 수렴. 제약 42.6%, 의료기기가 최고 성장 세그먼트.

**AI 규제업무는 성장률이 가장 높다** — 2025~26년 $1.7~1.9B, CAGR 19~23%. 최대 응용분야가 '규제 인텔리전스'(29.2%), APAC이 최고 성장률(22.5%).

**실질 타깃은 서비스 예산이다** — 규제 아웃소싱 $4.3B는 RIM 소프트웨어의 1.7배. AI 네이티브 플랫폼이 잠식할 수 있는 가장 현실적인 예산 풀.

> **주의** — RegTech 전체 시장은 리서치사별 CAGR이 6.75%~20%로 3배 차이. 단일 수치 인용은 부적절. 본 계획은 수렴도가 높은 RIM 수치를 기준으로 함. **한국 시장의 독립적 규모 추정치는 공개 자료에 존재하지 않음.**

## 6. Platform Vision — 하나의 규제 지식 레이어 위에 4개의 활용 축

**01. 규제 변화 모니터링 & 알림**
규제기관 원문을 수집·정규화하고 변경분(diff)을 추출. 제품·시장·사업부 프로파일에 매칭해 영향받는 조직에만 자동 통지.
*산출물: 일간 변경 브리핑, 영향도 등급, 담당자 지정 티켓*

**02. 규제 Q&A / RAG 어시스턴트**
자연어 질의에 대해 근거 조문·문서 버전·발효일을 함께 제시. 근거 없는 답변은 생성하지 않고 '확인 필요'로 반환.
*산출물: 인용 포함 답변, 원문 딥링크, 질의 이력 감사추적*

**03. 컴플라이언스 갭 분석 & 통제 매핑**
규제 요건을 구조화된 요구사항으로 분해하고 사내 SOP·통제·기술문서에 매핑. 개정 시 영향 범위와 미준수 항목을 자동 산출.
*산출물: 요건-통제 매트릭스, 갭 리포트, 조치 과제 목록*

**04. 외부 고객 대상 SaaS 제품화**
내부에서 검증된 워크플로를 멀티테넌트로 전환. 국내 제약·의료기기 기업 및 CRO/컨설팅사를 1차 타깃으로 상용화.
*산출물: 테넌트 격리, 밸리데이션 패키지, 파트너 API*

> 01–03은 내부 가치 검증 단계, 04는 동일 코어를 외부로 확장하는 단계 — 별도 제품이 아니라 같은 지식 레이어의 배포 형태 차이.

## 7. Data Strategy — 데이터 소스는 4개 티어로 나뉘고, 마지막 티어는 넘지 않는다

| 티어 | 구분 | 대상 | 제약 조건 |
|---|---|---|---|
| **A** | 공개 API — 즉시 수집 가능 | openFDA(의약품·의료기기·MAUDE·510(k)·PMA), Federal Register API, Regulations.gov API, Health Canada MDALL, 한국 국가법령정보 OPEN API, 공공데이터포털 MFDS 데이터셋 | openFDA 대부분 CC0 — 상업적 재배포 가능 |
| **B** | 정적 파일 / RSS — 배치 수집 | EMA 공개 JSON(1일 2회 갱신), FDA Orange/Purple Book, FDA AI 의료기기 목록, MFDS RSS(고시·입법예고·제개정) | 라이선스 조건 개별 확인 필요 |
| **C** | 스크래핑 — 취약성 관리 필요 | FDA 가이던스 DB·경고장·Form 483, EUDAMED(공식 API 없음), PMDA, NMPA, MHRA, TGA, MDCG 가이던스, ICH·IMDRF PDF | 구조 변경 감지·복구 파이프라인 필수 |
| **D** | 저작권 보호 — **원문 수집 금지** | ISO 13485 / 14971, IEC 62304 / 60601 / 62366, ISO 27001, USP-NF, Ph.Eur. 등 표준·약전 | ISO는 AI 학습 목적 사용을 명시적으로 금지 → 메타데이터·개정이력·인용만 다루고 정품 링크로 연결 |

> Tier D를 제품 경계선으로 명시하는 것이 리스크가 아니라 신뢰의 근거 — **'무엇을 수집하지 않는가'를 계약서에 쓸 수 있어야 규제 고객이 산다.**

## 8. Architecture — 5개 레이어, 수집에서 응용까지

**L1. 수집 (Ingestion)**
API 커넥터 · RSS · 스크래핑 워커 · 변경 감지 스케줄러 · 원문 불변 아카이브(WORM)

**L2. 정규화 (Normalization)**
문서 파싱 · 조문 단위 분할 · 다국어 번역(원문 병기) · 버전 관리 · 조문 단위 diff 추출

**L3. 규제 지식그래프 (Knowledge Graph)**
규제기관 · 법령/고시 · 조문 · 요구사항 · 제품군 · 시장 · 사내 SOP/통제를 엔티티로 연결. 개정 시 영향 전파 경로 계산

**L4. AI 레이어 (Retrieval & Reasoning)**
하이브리드 검색(BM25+벡터) · 그래프 기반 컨텍스트 확장 · 인용 강제 생성 · 근거 검증 에이전트 · 답변 신뢰도 스코어

**L5. 응용 (Applications)**
모니터링 대시보드 · Q&A 어시스턴트 · 갭 분석 워크벤치 · 알림/티켓 연동 · 멀티테넌트 SaaS 포털 · 공개 API

### 전 계층 공통 요건

- 출처·버전 메타데이터 필수 보존
- 전 조회·생성 이력 감사추적
- 21 CFR Part 11 전자기록·서명
- 역할 기반 접근제어(RBAC)
- 지역별 데이터 레지던시
- 모델 버전 고정 및 회귀 테스트

> **핵심 설계 원칙** — 지식그래프(L3)가 자산이다. LLM은 교체 가능하지만, 규제-제품-통제 매핑 데이터는 축적될수록 대체 불가능해진다.

## 9. Trust by Design — 규제 영역에서 AI의 승부처는 생성 품질이 아니라 검증 가능성

### 교훈: FDA 자체 AI 'Elsa'

- 2025년 7월 보도 — 존재하지 않는 논문을 생성하고 실제 연구를 왜곡, 그것도 확신에 찬 어조로 제시
- 직원 지적: "검증할 시간이 없는 결과물은 신뢰할 수 없다"
- 그럼에도 2026년 5월 FDA 심사관 90% 이상이 AI 활용 — 규제기관은 문제를 '사람 검토 절차'로 흡수하며 전진 중

### 설계 원칙 5가지

1. 근거 없는 답변 금지 — 인용 불가 시 '확인 필요' 반환
2. 조문 단위 인용 + 문서 버전 + 발효일 동시 제시
3. 생성 결과에 대한 별도 근거 검증 에이전트 통과 필수
4. 모든 답변에 신뢰도 스코어 표기, 임계값 미만은 사람 검토 라우팅
5. 질의·답변·근거 전체 감사추적 보존

### GxP 밸리데이션 — 외부 판매 시 반드시 통과해야 하는 관문

- **CSA 기반 밸리데이션** — FDA가 2025년 9월 Computer Software Assurance 가이던스를 최종 확정. 리스크 기반 접근으로 문서 부담은 줄었지만 공급자 산출물 요건은 유지
- **21 CFR Part 11 대응** — 감사추적의 위변조 방지, 전자서명 통제, 사용자 활동 로깅. SOC 2·ISO 27001만으로는 통과 불가
- **품질계약 & 감사권** — 데이터 보존 정책, 아카이브 무결성, 고객사 실사(audit) 수용 체계, 변경관리 문서
- **데이터 레지던시** — GDPR, 국내 개인정보보호법, 중국 데이터 규제 — 지역별 저장 위치를 계약 수준에서 답변 가능해야 함

*출처: CNN(2025.7.23) 및 FDA 발표(Elsa 4.0·HALO, 2026.5.6), Sidley GoodLifeSci(2026.5.20), FDA CSA 최종 가이던스(Federal Register, 2025.9.24), GxP 공급자 적격성 평가 실무 기준*

## 10. Roadmap — 3단계: 좁게 검증하고, 넓게 확장하고, 밖으로 판다

### Phase 1 · 0–4개월 — PoC
**범위를 좁혀 기술·가치 가설 검증**

- 대상: EU MDR + MFDS 의료기기 2개 규제영역
- Tier A/B 소스만 수집 (API·RSS)
- 모니터링 + Q&A 2개 기능만 구현
- 파일럿 사용자 1개 사업부 20~30명
- 결과: 확장 여부 Go/No-Go 판단

### Phase 2 · 5–12개월 — 내부 확장
**전사 적용 + 갭 분석 기능 추가**

- 규제영역 확대: FDA·EMA·PMDA·NMPA
- Tier C 스크래핑 파이프라인 구축
- 지식그래프 + 통제 매핑 구현
- 사내 SOP·기술문서 연동
- 결과: 전사 표준 도구화, ROI 실측

### Phase 3 · 13–24개월 — 외부 SaaS
**멀티테넌트 상용화 및 시장 진입**

- 멀티테넌트 아키텍처 전환
- GxP 밸리데이션 패키지 · SOC 2 취득
- 국내 제약·의료기기사 파일럿 고객 확보
- 파트너(CRO·컨설팅) 채널 구축
- 결과: 유료 고객 및 ARR 확보

> 각 단계 종료 시점에 정량 게이트를 통과해야 다음 단계 예산이 집행된다 — **단계별 승인 구조.**
